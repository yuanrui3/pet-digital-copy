# Pet digital copy

A web page with an animated 3D copy of one real house cat, built only from public research data and non-commercial
open models. It has two parts:
- **Body:** a reconstruction from a 12-second close-up phone video.
- **At home:** the cat in a phone-scanned room. It moves as it did in a month of home videos, and on walks generated by
  a behaviour model.

This repository holds the code and the written record only. The history is the pet part of a larger private
repository, split out on its own.

## Where to start

- `PROTOCOL_CAT.md`: everything about how the cat looks and moves at home. It records every attempt, what was
  measured, what was kept and why, in order. The latest sections are "Finishing the graft" (the live version, 22) and
  "The whole Body tab cat at home: one-day test" (an outside review and the test it led to).
- `PROTOCOL_BEHAVIOUR.md`, `PROTOCOL_STIMULUS.md`: the behaviour model (where the cat goes, how it reacts to people).
- `PROTOCOL.md`: the overall plan.
- `viewer/index.html`: the page (three.js; the cat is skinned on the CPU every frame).
- `cluster/`: the processing scripts, run on a GPU cluster (Python, numpy and scipy; Lab4D and Agent-to-Sim for the
  reconstructions).

## What is not here

- **The page's data files** (`viewer/data/`: meshes, bone motion, textures, room scan, sounds). They are too large, and
  are excluded from git.
- **Renders and model outputs:** they live on the cluster. The protocols describe them and give their numbers.
- **Public sources:** the source videos and datasets (Agent-to-Sim's cat videos and room scan, Lab4D's cat-85 set).

## Placeholders

Account details were replaced throughout the history:
- `USER`: the cluster username;
- `CLUSTER_HOST`: the cluster's login host;
- `/scratch/CLUSTER/`: its scratch space;
- "the cluster": its name.

Scripts that use these need them filled in before they run.
